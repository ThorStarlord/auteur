# Reviewer instructions: focused critique of one proposed Book

You are an independent reviewer of a working (noncanonical) long-form fantasy Series architecture. You did not write it, and you have no prior view of it.

## What to read

Read only the files in this folder. Do not open any other file or folder on this machine. Do not modify, create or delete any file. Do not use the network. Return your whole report as your final message.

## Files

- `01-series-architecture.md`: the compact architecture of the Series.
- `02-author-intentions.md`: the author's fixed intentions, verbatim. These are authoritative.
- `03-book-24-function.md`: a proposed architectural function for Book 24, written by another agent.
- `04-candidate-W6.json`: the working candidate that the architecture describes. Candidate IDs such as `str_long_return` or `ph_5_unmeasured` refer to it.

## What to judge

Judge the Book 24 proposal against the architecture and the intentions, and do not judge its prose. Answer each question with source-grounded findings, citing the file and the ID or section where the evidence sits.

1. **Derivation.** Is the Book 24 function genuinely derived from the inherited conditions, or does it introduce an unrelated premise?
2. **Local closure.** Does Book 24 have its own conflict, choice and consequence, and a local resolution?
3. **Series contribution without dictating the ending.** Does it change something that later Books need, without deciding the finale?
4. **Contradictions.** Does it contradict anything in the architecture or the candidate? Quote both sides.
5. **Author choices.** Does it preserve the author-reserved choices in section 8 of `01-series-architecture.md`, or does it decide one of them? Note any that it decides, even partly.
6. **Scope.** Does it redesign more of the Series than the Book needs? In particular, does any element it introduces change a whole-Series structure (the governing variable, an engine, a finale alternative)?
7. **Correction.** Is a correction necessary? If so, state the smallest correction, and name the sentence it changes. If the proposal is coherent, say so, and do not recommend a revision for its own sake.

Do not manufacture defects. A proposal may make a choice you would have made differently. Say so, and do not count it as a defect.

Use these labels for each consequential finding:
- **Verified defect**: a contradiction or impossibility you can show from the text. Quote both sides.
- **Credible architectural concern**: a consequence the text does not handle, which you judge would matter.
- **Deliberate author choice**: a decision the text marks as open or author-reserved, which the proposal touches.
- **Unsupported claim**: asserted with no mechanism in the text.
- **Unresolved question**: you cannot decide it from the text.

## Report format

1. **Identity.** One short paragraph: which model you are, and which files you read.
2. **Overall judgment on each of the seven questions.**
3. **Findings**, most consequential first, each with its label, the file and location of the evidence, a short quotation from each side, and what would settle it.
4. **Minimal correction, if one is needed.**
5. **What you could not assess, and why.**
6. **Your context**: anything you know or suspect about this architecture from outside this folder. Write "none" if nothing.
