## Findings & Repair Summary

### Finding 1: `FORCED_GENRE_RECOMMENDATION`
- **Original Classification**: GOLDEN_PATH_GAP (P1)
- **Corrected Classification**: GOLDEN_PATH_GAP (P1)
- **Observed Cause**: `recommend_genre_profile()` lacked pack-level domain applicability evaluation prior to subgenre profile ranking.
- **Fix**: Implemented `evaluate_pack_applicability()` in `src/auteur/genre_packs/recommendation.py`. When domain relevance score is below threshold (`NOT_APPLICABLE` or `WEAK_FIT`), the engine abstains and returns a `GenreRecommendationAdvisory` (`status="no_applicable_pack"`).
- **Evidence**: In Scenario B (Titan sci-fi murder mystery), `auteur genre recommend` output an advisory stating `status: not_applicable (score: 0.05)`, explaining missing domain signals, confirming zero state mutation, and providing recommended next actions instead of forcing `Erotic Psychological Drama`.

### Finding 2: `IDENTITY_RECOMMEND_REQUIRES_LLM_KEY`
- **Original Classification**: GOLDEN_PATH_GAP (P1)
- **Corrected Classification**: USABILITY_FRICTION / GOLDEN_PATH_GAP (P1)
- **Observed Cause**: `auteur identity recommend` initiated LLM calls without checking provider API keys, causing hidden retries and 4-attempt failures.
- **Fix**: Added upfront environment credential check in `src/auteur/cli_dispatch.py` for `identity recommend`. If `ANTHROPIC_API_KEY` or `OPENAI_API_KEY` is missing, it outputs concise setup instructions and points to `auteur identity init`. Implemented `handle_identity_init()` and registered `auteur identity init` CLI subcommand for offline skeleton generation.
- **Evidence**: Running `auteur identity recommend` without keys returns instant, friendly setup instructions with zero stack trace. Running `auteur identity init` generates a valid `story_identity.yaml` skeleton offline.

### Finding 3: `RECOMMENDATION_ACCEPT_REQUIRES_EXISTING_IDENTITY_FILE`
- **Original Classification**: USABILITY_FRICTION (P2)
- **Corrected Classification**: GOLDEN_PATH_GAP / USABILITY_FRICTION (P2)
- **Observed Cause**: `auteur genre recommendation accept` raised `[PACK_NOT_FOUND]` error when `story_identity.yaml` did not exist.
- **Fix**: Updated `dispatch_genre_pack_commands()` in `src/auteur/genre_packs/cli.py`. If `story_identity.yaml` is missing, it preserves the saved recommendation candidate in `.auteur/genre_recommendations/` and outputs clear, actionable guidance explaining how to run `auteur identity init` first.
- **Evidence**: Running `accept` on an empty project directory safely preserves candidate `rec_123` and returns exact step-by-step recovery commands.

### Finding 4: `SUBGENRE_VALIDATION_UNKNOWN_WARNING_FOR_PACK_PROFILES`
- **Original Classification**: QUALITY_LIMITATION (P3)
- **Corrected Classification**: DEFECT (P2)
- **Observed Cause**: `StoryIdentity.validate_identity()` checked legacy subgenre modifiers but neglected registered Genre Pack profile IDs.
- **Fix**: Updated subgenre validation in `src/auteur/identity.py` to inspect registered Genre Pack profile IDs via `get_pack_registry()`.
- **Evidence**: Validating a `StoryIdentity` containing `subgenres: [erotic_psychological_drama]` now passes with zero unknown-subgenre warnings.

## Pack Applicability & Abstention Audit

- **Applicability Model**: Separate pack domain applicability evaluation from profile ranking within a pack.
- **Abstention State**: `status: "no_applicable_pack"`, `mutated_state: false`.
- **Threshold Rationale**: Score >= 0.30 required for `APPLICABLE` status.
- **Scenario A Result**: `APPLICABLE` (score: 0.80+), recommended `erotic_psychological_drama` (88% confidence).
- **Scenario B Result**: `NOT_APPLICABLE` (score: 0.05), abstained with `no_applicable_pack` advisory.
- **Confidence Behavior**: Conditional profile score is ignored when overall pack applicability is low.
