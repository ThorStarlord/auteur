## F-01 — Negation-Aware Applicability

**Mechanism**: Deterministic phrase-based negation detection in `evaluate_pack_applicability()`. Three-layer heuristic:
1. **Global domain negation** — phrases like `"not an erotic"`, `"contains no erotic"`, `"attraction is not part"`, `"studies erotic"` zero out the score to 0.05 (NOT_APPLICABLE) if fewer than 2 un-negated signals remain.
2. **Local signal negation** — phrases like `"rejects desire"`, `"avoids intimacy"`, `"feels no attraction"` filter out the domain signal from `effective_matched`.
3. **Signal-local filter** — any domain signal whose text appears as a substring within a matched negation phrase is removed from `effective_matched`.

**Results**:
| Case | Status | Score | Matched | Negated |
|---|---|---|---|---|
| "This is not an erotic story" | NOT_APPLICABLE | 0.05 | [] | ["not an erotic"] |
| "The story contains no erotic content" | NOT_APPLICABLE | 0.05 | [] | ["no erotic"] |
| "Attraction is not part of the plot" | NOT_APPLICABLE | 0.05 | [] | ["attraction is not part"] |
| "She rejects desire and avoids intimacy" | NOT_APPLICABLE | 0.05 | [] | ["rejects desire", "avoids intimacy"] |
| "Scholar studies erotic literature" | NOT_APPLICABLE | 0.05 | [] | ["studies erotic"] |
| "She denies desire in public, but private longing drives every decision" | APPLICABLE | 0.95 | ["desire", "intimacy", "longing"] | [] |
| "He insists it's not romantic, while erotic obsession intensifies" | APPLICABLE | 0.80 | ["obsession", "romantic"] | [] |
| Marine biologist natural fit | APPLICABLE | 0.40 | ["longing"] | [] |
| Titan mystery | NOT_APPLICABLE | 0.05 | [] | [] |

**Known limitations**:
- Pronoun-coreference resolution not attempted ("It is not erotic" → `"it"` referring to a non-erotic work within the story would not be distinguished from global domain negation).
- Complex nested negation ("not entirely without erotic elements") is not handled.
- Requires exact phrase matching against the curated pattern list; variations not covered may slip through.

## F-02 — CLI Flag Consistency & Override Authority Confirmation

**Final override syntax**:
```
auteur genre recommendation override <recommendation-id> \
  --project <path> \
  --target <current-profile-or-field> \
  --replacement <new-profile-or-value> \
  --rationale <text> \
  --confirm
```

**Confirmation required**: Yes. `--confirm` is a `store_true` flag. Without it, `dispatch_genre_pack_commands()` returns exit code 1 with error message and zero mutation.

**Aliases**: None retained — clean single-path interface.

**Compatibility**: Current documented flags (`--project`, `--target`, `--replacement`, `--rationale`) continue working. `--confirm` is new required addition. Scripts lacking `--confirm` will fail with clear error.

**Human/JSON parity**: Error is emitted as structured JSON when `--json` flag is present. Both paths prevent mutation.

**Authority mutation**: Previously, `override` mutated `story_identity.yaml` without explicit confirmation. Now `--confirm` is enforced. Verified:
- `dispatch_genre_pack_commands()` raises error before calling `r_accept()` or `r_override()` when `confirm=False`.
- Regression test confirms zero mutation to `story_identity.yaml` when `--confirm` absent.

**`accept` subcommand**: Also patched — same `--confirm` check in the shared handler.
