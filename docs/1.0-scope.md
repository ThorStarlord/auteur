# Auteur 1.0 Support Scope

Auteur 1.0 is a local-first, single-author narrative engineering toolkit. The
release promise is a reliable, provenance-preserving path from an author
premise through accepted Story Identity, whole-story Blueprint and Structure,
bounded Scene/Chapter Realization and Expression, deterministic diagnostics,
proposal/decision/acceptance workflows, and HTML/EPUB publication.

## Supported release path

```text
premise
  → Story Discovery or Identity initialization
  → explicit Story Identity acceptance
  → Blueprint
  → whole-story Structure diagnosis/proposals
  → Chapter/Scene artifacts
  → optional LLM drafting and deterministic critics
  → explicit review, reconciliation, and acceptance
  → HTML/EPUB publication
```

The supported path is local and single-author. Canonical state is never changed
by recommendation, diagnosis, reasoning, simulation, publication, or tutor
output alone.

## Capability classification

| Capability | 1.0 status | Qualification expectation |
|---|---|---|
| Ontology, Identity, Blueprint, Structure | Supported | Schema, deterministic validation, CLI smoke, fixture coverage |
| Scene and Chapter Realization/Expression | Supported, bounded | Golden-path fixture and authority/freshness checks |
| Chapter and Book reconciliation | Supported, bounded | Candidate, publication, comparison, acceptance, completion tests |
| HTML and EPUB publication | Supported | Fresh installed-wheel smoke and deterministic artifact checks |
| Story Discovery and Genre Packs | Supported | Explicit acceptance and no-mutation golden path |
| Interactive Netorare, Mystery, Gentle Femdom pipelines | Supported | Shared-runtime and subprocess regression coverage |
| Workflow, Decision, Impact, Simulation, Portfolio, Commitment | Supported as coordination tools | Read-only/proposal authority and stale-input checks |
| Review sessions | Supported for inspection, choices, preparation, and recovery | Canonical acceptance must use the owning artifact command; generic review acceptance is deliberately fail-closed until an owner adapter exists |
| Book-level reasoning/editing | Experimental/bounded | Does not block core 1.0 unless explicitly promoted into the release promise |
| Long-horizon Tutor learning progression | Experimental | Requires human evidence of comprehension/transfer |
| Advanced Series context reconstruction | Experimental/bounded | Must remain derived and evidence-backed |
| Markerless mapping and paragraph movement | Deferred | No heuristic canonical mutation |
| Scene merge/split | Deferred | Requires a separate transformation contract |
| Grouped dependent decisions | Deferred | Requires an explicit transaction contract |
| Collaboration, cloud service, native GUI, payments, scraping, auto-publishing | Permanently out of scope | Must not be implemented as 1.0 work |

## Non-negotiable invariants

- Canonical mutation requires explicit author action, atomic persistence,
  provenance, rationale, and failure safety.
- Deterministic checks produce the same verdict for the same input.
- Derived artifacts never silently replace source contracts.
- Stale inputs block unsafe promotion; newer revisions are never substituted
  silently.
- The five semantic layers remain Ontology, Identity, Structure, Realization,
  and Expression. Scopes remain Universe, Series, Book, Chapter, and Scene.

## Release interpretation

“Supported” means the path is documented, tested, and included in installed
artifact qualification. “Experimental” means code may exist and be tested, but
the 1.0 support guarantee does not depend on it. “Deferred” means the absence
is intentional and must not be repaired by inference or a parallel subsystem.
