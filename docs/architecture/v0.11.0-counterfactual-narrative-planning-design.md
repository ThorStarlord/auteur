# Auteur v0.11.0 — Counterfactual Narrative Planning

## Overview

v0.11.0 adds a deterministic **Counterfactual Narrative Planning** subsystem
that lets an author compare the projected downstream consequences of multiple
candidate decisions without mutating accepted, canonical, planning, decision,
impact, or review state.

It composes v0.10 project planning with an isolated scenario overlay model:
real state is captured in an immutable baseline, candidate-specific hypothetical
deltas are applied as an overlay, and existing impact and planning engines
operate on the overlaid state to produce projections.

### Central invariant

> Counterfactual projection is not creative judgment, acceptance, canonical
> mutation, or prediction presented as fact.

## Architecture

### Package structure

```
src/auteur/simulation/
    __init__.py        — exports and public API
    models.py          — scenario, baseline, assumption, consequence, comparison contracts
    baseline.py        — immutable capture of current project state
    overlay.py         — isolated candidate-specific hypothetical state
    projection.py      — candidate-specific impact and plan projection
    comparison.py      — semantic comparison of scenarios
    uncertainty.py     — evidence classes, confidence, and unknowns
    persistence.py     — immutable baselines, scenarios, projections, comparisons
    promotion.py       — safe delegation into Author Review Sessions
    service.py         — application-service boundary for CLI and workflow
    cli.py             — presentation and argument parsing only
```

### Reused existing systems (NOT duplicated)

| Capability | Reuses |
|-----------|--------|
| Decision data | `DecisionWorkspaceService.list_decisions()`, `.inspect()` |
| Candidate data | Decision `candidates` list, provenance |
| Impact projection | `ImpactStore`, `ImpactAnalyzer` (via overlay) |
| Project planning | `PlanningService.refresh()`, `Planner`, `MilestoneEngine` (via overlay) |
| Critical path | `CriticalPathAnalyzer` (via overlay) |
| Review creation | `ReviewService.start_session()` |
| Authority model | `AuthorityLevel` from workflow |
| Persistence pattern | `PlanStore` immutable snapshot + atomic latest pointer |

## Core models

### CounterfactualBaseline

Immutable snapshot of real project state at a point in time.

| Field | Description |
|-------|-------------|
| `baseline_id` | Stable SHA-256 prefix for identity |
| `project` | Project root path |
| `plan_id` | Current project plan ID |
| `decision_ids` | IDs of open decisions |
| `accepted_pointers` | Dict of artifact type → accepted revision |
| `canonical_pointers` | Dict of artifact type → canonical revision |
| `provenance_hashes` | Dict of artifact path → content hash |
| `created_at` | ISO timestamp |
| `schema_version` | Schema version |
| `tool_version` | Auteur version |

### CounterfactualScenario

An isolated hypothetical scenario based on one candidate.

Identity formula: `stable_id(project, baseline_id, decision_id, candidate_id, normalized_assumptions, schema_version)`

| Field | Description |
|-------|-------------|
| `scenario_id` | Stable SHA-256 prefix |
| `state` | Scenario lifecycle state |
| `baseline_id` | Reference to immutable baseline |
| `decision_id` | Decision being evaluated |
| `candidate_id` | Candidate under consideration |
| `candidate_snapshot` | Snapshot of candidate data at creation |
| `assumptions` | List of `ScenarioAssumption` |
| `projected_consequences` | List of `ProjectedConsequence` |
| `projected_plan` | Optional `ProjectedPlan` |
| `projected_critical_path` | Optional `ProjectedCriticalPath` |
| `uncertainty_summary` | Text summary of unknowns |
| `source_hashes` | Dict of source → hash for staleness |
| `schema_version`, `tool_version` | Versioning |

### ScenarioAssumption

An explicit assumption underlying the projection.

| Field | Description |
|-------|-------------|
| `assumption_id` | Stable ID |
| `description` | Human-readable text |
| `is_default` | Default or user-supplied |
| `category` | `structural`, `procedural`, `semantic` |

### ProjectedConsequence

A single projected consequence.

| Field | Description |
|-------|-------------|
| `consequence_id` | Stable ID |
| `target` | Artifact/decision/session reference |
| `description` | Human-readable text |
| `classification` | `KNOWN`, `DERIVED`, `INFERRED`, `UNKNOWN` |
| `confidence` | `CERTAIN`, `HIGH`, `MEDIUM`, `LOW`, `UNDETERMINED` |
| `supporting_evidence` | References to backing data |
| `assumptions` | Assumptions this consequence depends on |
| `reversibility` | Whether the effect is reversible |
| `projected_action` | What action this consequence implies |

### Scenario comparison

Comparison output includes:

- Shared consequences between scenarios
- Scenario-specific consequences
- Opposing consequences
- Evidence asymmetry
- Uncertainty asymmetry
- Unknowns preventing responsible comparison

No winner score, best candidate, or artistic recommendation.

## Scenario lifecycle

```
CREATED → VALIDATING → READY → PROJECTING → PROJECTED → COMPARABLE
                                                                  ↓
                                                            PROMOTED
                                                         or DISCARDED
                         changes detected → STALE → refresh → new lineage
                         projection error → FAILED (inspectable)
```

## Overlay model

The overlay avoids cloning the entire repository:

```python
class ScenarioOverlay:
    """Hypothetical state view over an immutable baseline."""
    baseline: CounterfactualBaseline
    resolved_decision_id: str
    selected_candidate_id: str
    stale_artifact_ids: set[str]
    projected_new_decisions: list[dict]
    projected_milestone_changes: dict[str, str]
    # ... delta entries
```

The overlay is passed to existing planning and impact engines instead of real
state. No live store is touched.

## CLI

```
auteur simulate create            — create counterfactual scenario
auteur simulate status            — show simulation status
auteur simulate inspect <id>      — inspect scenario
auteur simulate project <id>      — run projection
auteur simulate compare <a> <b>   — compare scenarios
auteur simulate refresh <id>      — refresh stale scenario
auteur simulate promote <id>      — promote into review
auteur simulate discard <id>      — discard scenario
auteur simulate history [id]      — show history
auteur simulate list              — list scenarios
```

## Promotion boundary

Promotion calls `ReviewService.start_session()` with the scenario candidate.
It attaches scenario and comparison references as evidence. It does NOT:
record an author choice, accept a candidate, move canonical pointers, or
copy hypothetical state into live state.

## Deferred scope

- Automatic artistic winner selection
- Story-quality scores
- Fake confidence percentages
- Reader-response or market-success prediction
- Manuscript generation inside simulations
- Full repository cloning
- Git branches as scenario storage
- Acceptance from simulation
- Automatic review abortion or publishing
- GUI-first architecture or cloud collaboration
