# v0.34.0 — Structural Revision Phase 3

## Objective

Connect Auteur's existing structural diagnosis, proposal, impact analysis,
and freshness capabilities into a rigorous revision lifecycle with scoped
plans, authority-gated application, impact reconciliation, re-evaluation,
and auditable completion.

## Architecture

```
diagnostic or structural proposal
  ↓
RevisionPlanner — creates scoped revision plan
  ↓
RevisionService — validates, gates authority, coordinates lifecycle
  ↓
RevisionApplication — applies operations through owning APIs
  ↓
RevisionReconciliation — impact + freshness + re-evaluation
  ↓
completion or supersession
```

## Modules

```
src/auteur/structure/
    revision_models.py     — typed plan, operation, result, event contracts
    revision_planner.py    — convert diagnostics/proposals into plans
    revision_service.py    — lifecycle coordination
    revision_application.py — validate and delegate mutations
    revision_reconciliation.py — impact, freshness, re-evaluation
    revision_history.py    — immutable plans, applications, events
```

## Core models

- StructuralRevisionPlan — stable semantic ID, targets, operations, scope
- RevisionOperation — typed (ADD, REMOVE, REPLACE, etc.)
- RevisionScope — declared mutation boundary
- RevisionApplication — before/after evidence per target
- RevisionCompletion — reconciliation + re-evaluation results

## CLI surface

```
auteur structure revision plan --proposal <id>
auteur structure revision inspect <plan-id>
auteur structure revision validate <plan-id>
auteur structure revision apply <plan-id> --confirm
auteur structure revision reconcile <application-id>
auteur structure revision reevaluate <application-id>
auteur structure revision status <id>
auteur structure revision history [plan-id]
auteur structure revision supersede <plan-id> --confirm
auteur structure revision abort <plan-id> --confirm
auteur structure revision list
```

## Authority invariants

- planning ≠ application
- validation ≠ authorization
- confirmation required for mutation
- revision ≠ acceptance
- no pointer mutation without authorized path
