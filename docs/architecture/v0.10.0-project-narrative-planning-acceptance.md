# Auteur v0.10.0 Acceptance Report — Project-Level Narrative Planning

## Summary

v0.10.0 adds a deterministic **Project-Level Narrative Planning** subsystem.
It composes v0.5 impact analysis, v0.7 decisions, v0.8 orchestration, and v0.9
review sessions into a project-wide planning layer.

### Architecture

```
src/auteur/planning/
    __init__.py          — exports and public API
    models.py            — plan, node, edge, milestone, path, action, snapshot contracts
    graph.py             — decision and milestone dependency graph
    assembler.py         — load real state from decision, review, impact, provenance
    milestones.py        — derive and evaluate project milestones
    critical_path.py     — compute deterministic blocking paths and leverage
    coordinator.py       — session conflicts, staleness, safe parallel work
    planner.py           — produce ordered actions and project plans
    persistence.py       — immutable plan snapshots and atomic latest pointers
    service.py           — application-service boundary used by CLI and workflow
    cli.py               — rendering and argument handling only
```

### Graph model

- **PlanningNode types**: DECISION, REVIEW_SESSION, MILESTONE, REFRESH
- **DependencyType**: PREREQUISITE, BLOCKS, INVALIDATES, REQUIRES_EVIDENCE_FROM, REQUIRES_ACCEPTANCE_OF, REQUIRES_REVIEW_COMPLETION, REFRESH_AFTER, SUPERSEDES
- **DependencyStrength**: HARD, SOFT, INFORMATIONAL
- Features: deterministic node/edge ordering, transitive dependencies, cycle detection, subgraph extraction by horizon

### Dependency semantics

Every edge carries:
- `edge_id` (stable hash)
- `source_id`, `target_id`
- `dependency_type`, `strength`
- `reason` (human-readable)
- `evidence` (optional DependencyEvidence with subsystem, artifact, freshness)

### Milestone model

System-derived milestones based on real artifact and authority state:

- Story Identity accepted
- Structure valid
- Chapter N realization accepted
- Chapter N expression accepted
- Chapter N reasoning current
- Chapter N reconciliation complete
- Book assembled / accepted
- Publication current

States: NOT_STARTED, IN_PROGRESS, BLOCKED, READY, COMPLETED, STALE

### Critical-path formula

```
leverage = (direct_blocked × 1.0)
         + (transitive_blocked × 0.5)
         + (blocked_milestones_blocking × 10)
         + (blocked_milestones_in_progress × 5)
         + (authority_required × 3)
         + (stale × 2)
         - (parallel_workaround × 1)
```

Labelled "blocking critical path", not "creative priority".

### Parallel-work policy

Two actions are parallel-safe only when ALL of:
1. No hard dependency exists
2. No shared authority-bearing target
3. No active review session conflict
4. Neither action invalidates the other's source state
5. Both actions are independently fresh

### Session coordination

Findings classify: COMPATIBLE, ORDER_REQUIRED, STALE, CONFLICTING, SUPERSEDED, BLOCKED

### Workflow integration

WorkflowEngine consumes plan recommendations via `plan refresh`. Safe actions
may execute through workflow; author-required actions remain refused.
No workflow recursion. Failed child commands do not advance plan state.

### CLI examples

```
auteur plan status              # show plan summary
auteur plan graph               # show dependency graph
auteur plan next                # show recommended next action
auteur plan critical-path       # show blocking critical path
auteur plan milestones          # show milestone state
auteur plan explain <id>        # explain node or action
auteur plan refresh             # create fresh plan snapshot
auteur plan history             # show plan history
auteur plan list                # list plan snapshots
auteur plan render <bp> <ch>   # legacy cartographer render
```

All commands support `--project` and `--json`.

### Deferred scope

- Calendar scheduling
- Duration estimation from LLMs
- Team assignments, collaboration
- Cloud synchronization
- Generic issue tracking
- Gantt charts
- Automatic artistic prioritization
- Automatic acceptance / session abortion
- Manuscript rewriting
- Database migration
- GUI-first architecture
- Background distributed workers
- User-defined milestones (to v0.11.0+)

## Limitations

1. User-defined milestones deferred to v0.11.0+
2. No calendar scheduling or duration estimation
3. Graph-based critical path is structural, not creative priority
4. Safe parallel work is planning guidance, not a scheduler
5. Plan assembly depends on subsystem availability; missing subsystems produce partial plans
6. Lacks a full plan-diff command (deferred)
