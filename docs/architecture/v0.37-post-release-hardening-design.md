# Auteur v0.37.x — Post-Release Reliability and Usability Hardening Design

## Overview
This document records the architectural and heuristic design decisions for the v0.37.x bounded post-release hardening pass. It addresses three specific P3 findings identified during the v0.37.0 post-release dogfood review (`docs/reviews/v0.37-post-release-golden-path-review.md`).

## Findings Addressed

### F-01: Negation-Aware Applicability Evaluation
- **Defect**: Lexical keyword matching counted words like `"erotic"` even when preceded by explicit domain negation (e.g. `"This is not an erotic story"`) or academic/analytical framing (`"a scholar studies erotic literature"`), leading to false-positive applicability scores (0.40).
- **Intended Behavior**:
  - Deterministically identify explicit global domain negation phrases (e.g., `"not an erotic story"`, `"contains no erotic content"`, `"attraction is not part of the plot"`).
  - Identify mention-without-embodiment patterns (e.g., `"studies erotic literature"`, `"analyzes erotic horror"`).
  - Differentiate explicit domain negation from in-domain character denial/resistance (e.g., `"She denies her desire in public, but private longing drives her"`).
  - Reduce applicability score to 0.05 (`NOT_APPLICABLE`) when domain negation is present without overwhelming positive domain evidence.
- **Non-Goals**: Unrestricted natural language processing (NLP) or non-deterministic LLM calls during structure applicability evaluation. Heuristics remain narrow, explainable, and deterministic.

### F-02: CLI Flag Consistency & Override Authority Confirmation
- **Defect**: `auteur genre recommendation override` mutated Layer 1 `story_identity.yaml` without requiring explicit author confirmation via `--confirm`.
- **Intended Behavior**:
  - Require `--confirm` flag on `auteur genre recommendation override` to enforce Auteur's authority model (no silent state mutation).
  - Ensure `--target`, `--replacement`, `--rationale`, and `--confirm` flags are enforced consistently.
  - Return clear, typed error and instructions if `--confirm` is omitted.
  - Align human text and JSON output schemas across `accept`, `override`, and `inspect`.

### F-03: Pydantic V2 Warning Elimination
- **Defect**: Importing `scene_state.py` produced repetitive `PydanticDeprecatedSince20` warnings on Python console due to class-based `class Config:` declarations.
- **Intended Behavior**:
  - Migrate models (`KnowledgeFact`, `EmotionalState`, `EntryState`, `ExitState`) in `src/auteur/narrative_realization/schema/scene_state.py` to Pydantic V2 `model_config = ConfigDict(...)`.
  - Maintain exact field serialization, validation semantics, and schema compatibility.
  - Eliminate deprecation warning output during imports and test execution.

## Backward Compatibility & Safety Guarantees
- No changes to existing Layer 1 or Layer 2 blueprint schemas.
- Existing saved recommendation candidates remain 100% compatible.
- Zero feature additions or expansion into new Genre Packs in this branch.
