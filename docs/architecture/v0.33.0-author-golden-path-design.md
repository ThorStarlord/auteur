# v0.33.0 — Author Golden Path Qualification

## Objective

Prove that Auteur's capabilities form a coherent author-facing product.
An author should be able to begin with a narrative problem and reach a
justified, current, publishable result without understanding Auteur's
internal subsystem architecture.

## Canonical command hierarchy

```
auteur dashboard
  → broad project overview, primary next action

auteur workflow next
  → one authoritative recommended next action

auteur workflow explain
  → why that action is recommended, what blocks progress

specialized subsystem commands
  → inspect or execute the recommended action
```

## Journey state model

```
current_stage ∈ {identity, structure, realization, drafting,
                 reasoning, reconciliation, acceptance, assembly, publishing}
blocking_condition ∈ {missing_artifact, stale_artifact, unresolved_finding,
                      authority_required, divergence_detected, none}
freshness_state ∈ {current, stale, diverged}
authority_requirement ∈ {read_only, derived, candidate, proposal,
                         authority_bearing, canonical_mutation}
```

## Cross-surface consistency invariant

For the same persisted project state, all surfaces must agree on:
- current stage
- blocking condition
- freshness state
- authority requirement
- recommended next action
- completion readiness

Surfaces may expose different detail levels but must not contradict.

## Semantic ownership

| Concept | Owner | Persisted state | Derived views |
|---------|-------|----------------|---------------|
| workflow state | WorkflowEngine.analyze() | computed from artifact state | dashboard, status |
| lifecycle state | LifecycleService | .auteur/lifecycle/ | workflow, dashboard |
| commitment progress | CommitmentService | .auteur/commitment/ | workflow, dashboard |
| notification alerts | NotifyService | .auteur/notify/ | dashboard, workflow next |
| reasoning findings | ReasoningRuntime | .auteur/reasoning/ | workflow explain |
| structural proposals | structure/proposals/ | .auteur/structure/proposals/ | structure propose |
| accepted artifacts | expression stores | book/expression/, chapters/*/expression/ | workflow, status |
| publishable artifacts | PublishingSnapshot | computed | publish |

## Completion semantics

A journey is complete when:
1. The recommended next action reaches a terminal state
2. No blocking conditions remain
3. All required decisions have been made through authorized paths
4. Freshness is current across the affected artifact chain
5. The result can be published from current accepted state

## Author journeys

### Journey A — Repair a chapter-level structural problem

1. `auteur dashboard` → shows chapter needs structural repair
2. `auteur workflow next` → recommends structural diagnosis
3. `auteur structure diagnose <blueprint>` → finds structural weakness
4. `auteur structure propose-repairs <blueprint>` → generates proposals
5. `auteur structure apply <proposal> <blueprint> --in-place` → apply with authority
6. Freshness propagation updates hashes automatically
7. `auteur structure publish --project .` → publishes current structure

### Journey B — Resolve interacting narrative decisions

1. `auteur workflow next` → recommends simulation
2. `auteur simulate create ...` → runs scenario
3. `auteur portfolio generate` → builds portfolio
4. `auteur portfolio combine` → compares candidates
5. `auteur commit create` → commits to a direction
6. `auteur commit accept <id> --confirm` → explicit authority
7. Lifecycle advances; commitment updates

### Journey C — Improve and publish a scene

1. `auteur dashboard` → shows scene needs revision
2. `auteur workflow explain` → shows scene reasoning finding
3. `auteur reasoning book` → runs book-level scene analysis
4. Scene revision through authorized path
5. `auteur scene publish --project .` → publishes current scene
