# Premise Fitness Coding-Agent Stress Test

**Status:** controlled coding-agent simulation  
**Scope:** answer two post-calibration product questions without new human input  
**Authority:** product-mechanics evidence only; not human preference or audience evidence

## Questions

1. Do repeated author/agent uses of Premise Fitness expose enough operational
   value to justify a dedicated runtime?
2. Does architecture-aware Premise Fitness reassessment after Story Discovery
   add meaningful decision value?

## Evidence boundary

This stress test may establish:

- whether the documented method is repeatable by a coding agent;
- whether repeated use creates operational friction that a runtime could remove;
- whether post-Discovery architecture changes produce premise-fitness deltas;
- where a proposed reassessment duplicates existing Story Discovery F3/F4 or
  MANA responsibilities.

It does not establish:

- broad writer preference;
- cognitive load, joy, ownership, or desire to continue;
- live-provider creative quality;
- commercial success;
- population-level effectiveness.

Prior evidence used as constraints:

- six-case Phase E founder creative adjudication;
- five-case Phase F coding-agent Story Discovery regression;
- ten-case Premise Fitness calibration;
- four-premise Beginner-flow headless probe.

The simulation does not replace issue #305 real-author evidence or #310
live-provider evidence.

---

# 1. Q1 — Does Premise Fitness deserve a dedicated runtime?

## Protocol

The coding agent applies the documented method across repeated changes rather
than isolated static examples.

The stress conditions deliberately include:

1. unknown scope;
2. known scope changed after first analysis;
3. Genre Pack available;
4. no relevant Genre Pack;
5. multi-genre hierarchy;
6. deconstructive posture;
7. premise revision that strengthens the governing engine;
8. comparison of several candidate premises for one target environment.

The test asks two different questions:

> Can the coding agent perform the reasoning consistently from documentation?

and:

> Does the work create enough repeated state/provenance/recomputation burden that
> a dedicated runtime is currently justified?

---

## Q1-A — Unknown scope

Premise:

> A girl discovers that every dream she forgets becomes a real person.

The documented method produces conditional short / novel / series analysis
without selecting a horizon.

### Runtime value observed

Low.

The reasoning is compact and does not require persistence.

### Finding

Documentation is sufficient.

---

## Q1-B — Scope changes after analysis

Same premise:

Initial target:

    novella

Later target:

    six-book series

The agent must revisit:

- runway;
- renewability;
- expansion capacity;
- complexity cost;
- scope fit;
- repair options.

### Runtime value observed

Moderate.

A structured runtime could retain the previous target and show a fitness delta,
but the agent can still perform the reassessment correctly from the docs.

### Finding

Useful automation opportunity, not yet a dedicated-runtime requirement.

---

## Q1-C — Genre Pack available

Premise:

> Two rivals rebuild a theater while resolving a disputed family claim.

Target:

    romance novel

Available genre knowledge can supply romance promises, escalation patterns,
failure modes, and subversion points.

### Runtime value observed

Moderate.

A runtime could retrieve and cite pack knowledge deterministically, reducing
manual lookup and making provenance explicit.

### Finding

Integration with reusable genre knowledge is a plausible runtime benefit.

---

## Q1-D — No Genre Pack

Premise:

> A civilization survives by transferring legal obligations between alternate
> timelines.

Target genre is not represented by a dedicated pack.

The documented fallback works:

    generic craft reasoning
    + explicit heuristic status
    + lower genre-specific specificity

### Runtime value observed

Low.

A runtime does not create missing knowledge merely by existing.

### Finding

No-pack cases do not justify runtime.

---

## Q1-E — Multi-genre hierarchy

Premise:

> Recovering abandoned planetary systems changes rival civilizations and the
> protagonist's relationships on Earth.

Target hierarchy:

    primary: civilizational political progression
    secondary: relationship drama
    tertiary: mystery
    local mode: cosmic horror

The agent repeatedly checks:

- primary-engine support;
- secondary-engine attachment;
- shared causal events;
- complexity cost;
- hierarchy displacement risk;
- scope fit.

### Runtime value observed

Moderate-to-high when repeated across many alternatives.

The reasoning itself remains understandable, but comparison state becomes
laborious.

### Finding

Batch/candidate comparison is a stronger runtime use case than single-premise
analysis.

---

## Q1-F — Deconstructive posture

Premise:

> Greater romantic intimacy progressively reduces each partner's independent
> agency.

The agent correctly evaluates genre legibility relative to declared
deconstructive posture rather than conventional compliance.

### Runtime value observed

Low.

The main value comes from the conceptual rule and Genre Pack knowledge, not from
runtime state.

### Finding

Documentation is sufficient for a single analysis.

---

## Q1-G — Premise revision

Version 1:

> A magical university exists beneath Sao Paulo.

Finding:

    EVOCATIVE PREMISE
    GOVERNING ENGINE UNESTABLISHED

Version 2:

> A scholarship student must earn magical citizenship beneath Sao Paulo while
> every exam transfers one of her memories to the rival grading her.

The second version materially changes:

- engine strength;
- activation;
- progression support;
- relationship pressure;
- runway;
- scope fit.

### Runtime value observed

Moderate.

A structured delta report would be useful because premise revisions are likely
to recur during opportunity discovery.

### Finding

Revision comparison is a plausible retained runtime use case.

---

## Q1-H — Batch premise comparison

Target:

    five-book speculative mystery series
    broad entry
    moderate complexity

Compare four candidate premises.

The coding agent can evaluate them from documentation, but must repeatedly
reconstruct:

- identical target environment;
- fitness dimensions;
- evidence states;
- unknowns;
- repair classes;
- cross-candidate tradeoffs.

### Runtime value observed

High relative to all prior Q1 conditions.

The burden is not reasoning difficulty; it is repeated normalization,
provenance, and comparison.

### Finding

If Auteur frequently compares multiple Story Opportunities against one target
environment, a small structured Premise Fitness capability becomes useful.

---

## Q1 synthesis

The simulation separates two claims.

### Claim A — Is the method agent-usable without runtime?

**Yes.**

The documentation is sufficient for isolated and occasional analysis.

### Claim B — Is a dedicated standalone runtime warranted now?

**No.**

The simulation does not show enough value for a new standalone subsystem merely
to reproduce prose analysis that an agent can already perform.

The strongest automation cases are narrower:

- persistent target-environment state;
- batch candidate comparison;
- premise-revision delta;
- deterministic Genre Pack retrieval/provenance;
- repeated re-evaluation after upstream changes.

### Q1 disposition

    DOCUMENTED METHOD
    SUFFICIENT FOR SINGLE / OCCASIONAL USE

    STRUCTURED AUTOMATION
    PLAUSIBLY USEFUL FOR REPEATED COMPARISON / DELTA WORK

    DEDICATED STANDALONE RUNTIME
    NOT YET WARRANTED

A future implementation should therefore prefer a small read-only capability
inside an existing reasoning/comparison surface over a new major Premise Fitness
subsystem.

# 2. Q2 — Does architecture-aware reassessment add value after Story Discovery?

## Protocol

For each case, compare:

    premise-stage fitness
    vs
    Story Discovery architecture
    vs
    architecture-aware fitness delta

Then ask:

1. Did the post-Discovery pass discover information that could not be known from
   the premise alone?
2. Is that information already owned by Story Discovery F3/F4 or MANA?
3. If useful, what is the narrow non-duplicative responsibility?

---

## Q2-A — Retired astronaut / mission-control chatter

Premise:

> A retired astronaut hears mission-control chatter in her empty apartment.

### Before Story Discovery

The premise can support speculative mystery/drama, but intent and governing
engine are under-specified.

Fitness can identify:

- evocative hook;
- potential low activation cost;
- unresolved genre/experience target;
- governing engine not yet sufficiently established.

### After Story Discovery

Different candidate architectures can assign causal weight to:

- an external mystery;
- psychological/relational interpretation;
- present-day obligation caused by the transmissions.

### New fitness information

Yes.

Once a governing architecture exists, the agent can evaluate:

- whether the chosen engine can sustain the declared horizon;
- whether secondary mechanisms increase activation/complexity;
- whether the architecture resolves the earlier engine ambiguity.

### Overlap

Story Discovery owns candidate generation and recommendation.

Premise Fitness adds value only as a **target-fit delta**, not as another
candidate judge.

### Result

Meaningful but narrow value.

---

## Q2-B — Impossible murder in one elevator

Premise target:

    fair-play closed-circle mystery
    physically possible solution
    one elevator
    six strangers

Premise-stage fitness is already strong:

- clear genre promise;
- tight activation;
- naturally finite novel/novella runway;
- low world-model cost.

Story Discovery produced a primary physical-opportunity engine plus possible
identity and epistemic layers.

### New fitness information after architecture

Yes, but modest.

The post-Discovery pass can identify:

- whether subordinate layers increase complexity beyond the tight closed-circle
  promise;
- whether the primary physical engine remains governing;
- whether composition changes payoff density or clue burden.

### Overlap

F4 already assesses composability and displacement risk.

### Result

A full second Premise Fitness analysis would duplicate F4.

A narrow scope/complexity/runway delta may still be useful.

---

## Q2-C — Museum heist

Premise constraints create a strong heist opportunity:

    nothing stolen
    nobody knowingly lies
    corrupt director defeated
    museum essential

Premise-stage fitness can say the constraints create a strong action engine.

Story Discovery later discovered that two supposed alternatives could collapse
into the same causal chain.

### New fitness information after architecture

The important new information is causal distinctness.

### Overlap

This is explicitly Story Discovery F3's responsibility.

### Result

Architecture-aware Premise Fitness should **not** duplicate this check.

If the architecture is F3-qualified, Premise Fitness may consume that result but
should not independently re-adjudicate candidate distinctness.

---

## Q2-D — Shrinking inherited house

Premise:

> A family inherits a house that loses one room every night.

Premise-stage fitness:

- strong supernatural-horror efficacy;
- rapid activation;
- good finite-to-novel runway;
- family relationship engine available.

Story Discovery distinguishes relational, containment, and restitution engines
and permits a primary-with-layers architecture under maximalist/mixed-causation
intent.

### New fitness information after architecture

Yes.

The final architecture determines:

- how many engines are actually active;
- whether they share causal events;
- added entity/information cost;
- whether maximalism remains legible;
- whether the chosen horizon still fits the resulting complexity.

### Overlap

F4 explains craft-layer propagation and hierarchy.

Premise Fitness can add a **cost/scope consequence** view without repeating the
craft explanation.

### Result

Meaningful narrow delta.

---

## Q2-E — Brother caused disaster / protagonist never learns

Premise-stage analysis can identify:

- strong dramatic-irony affordance;
- finite novel horizon;
- relationship/secret pressure.

Story Discovery adds:

- protagonist recovery as primary engine;
- brother atonement as subordinate causal layer;
- institutional epistemic layer.

### New fitness information after architecture

Yes.

The architecture may increase:

- hidden-intervention scene load;
- causal distribution;
- complexity;
- payoff latency;
- risk of protagonist displacement.

### Overlap

F4 already explains the causal-ownership and scene-family shift.

### Result

Premise Fitness should not repeat the same explanation.

Its useful contribution is whether the added layer changes:

- declared scope fit;
- activation burden;
- maintenance cost;
- engine renewability;
- primary/secondary compatibility.

---

## Q2-F — Fixed history / time traveler as witness

Premise:

> History cannot be changed; a time traveler can only change what the trip means
> to people who remember it.

Premise-stage fitness:

- clear conceptual constraint;
- strong philosophical/dramatic efficacy;
- finite-to-novel scope plausible;
- meaningful agency must be nonhistorical.

Story Discovery can place primary causal weight on:

- witness -> knowledge -> obligation -> present action;
- relationship recurrence;
- institutional/public-memory action.

### New fitness information after architecture

Yes.

The architecture materially changes:

- action families;
- number of active causal domains;
- complexity;
- payoff cadence;
- expansion potential.

### Overlap

Again, F4 explains craft propagation.

### Result

A post-Discovery **fitness delta** is useful; a second full recommendation system
is not.

---

# 3. Q2 synthesis

Architecture-aware reassessment **does add meaningful value**, because Story
Discovery resolves variables that premise-stage analysis cannot know:

- actual governing engine;
- engine hierarchy;
- causal ownership;
- selected subordinate mechanisms;
- resulting complexity;
- resulting action/scene burden.

However, existing Story Discovery already owns much of the semantic explanation:

- F3 — causal distinctness;
- F4 — craft-layer propagation / composability / displacement risk.

MANA separately owns audience-effect analysis.

Therefore a full second Premise Fitness subsystem would create overlap.

The non-duplicative responsibility is narrower:

> **Post-Discovery Premise Fitness Delta**

It should ask only:

- Did the selected architecture change activation cost?
- Did it change complexity/maintenance burden?
- Did it change runway or renewability?
- Did it change expansion capacity?
- Did it change multi-engine compatibility?
- Did it change scope fit?
- Did it resolve an earlier `GOVERNING ENGINE UNESTABLISHED` finding?
- Did accepted target-environment assumptions change?

It should consume Story Discovery's causal/craft findings rather than recreate
them.

### Q2 disposition

    ARCHITECTURE-AWARE REASSESSMENT
    MEANINGFUL VALUE: YES

    FULL SECOND FITNESS SYSTEM
    WARRANTED: NO

    NARROW POST-DISCOVERY FITNESS DELTA
    WARRANTED CONCEPTUALLY: YES

    RUNTIME IMPLEMENTATION
    DEFER UNTIL REPEATED USE / INTEGRATION NEED

# 4. Relationship to prior user testing

The repository has already performed substantial controlled testing.

## Actual founder / owner creative judgment

Phase E:

- six cases;
- direct founder reactions;
- enough convergence to stop the synthetic founder loop;
- established value for intent-aware Story Discovery when candidate engines are
  causally distinct.

This is genuine owner/founder evidence, but not a broad writer study.

## Coding-agent regression

Phase F:

- five controlled cases;
- reused frozen Phase E criteria;
- verified implementation mechanics;
- explicitly did not claim fresh human preference.

## Premise Fitness calibration

Current PR #312:

- ten synthetic craft cases;
- verified conceptual discrimination;
- not human usefulness evidence.

## Beginner-flow mechanical probe

PR #309:

- four premise families;
- compared 22 / 8 / 2 designed interactions;
- established mechanics and authority boundaries;
- not subjective usability/preference.

## Still outstanding

Issue #305 remains the explicit real-author ergonomics comparison.

Issue #310 remains the live-provider Quick Draft dogfood.

Therefore:

> We have already done many high-information founder, agent, and synthetic tests.

But:

> We have **not** completed repeated independent-user validation of Premise
> Fitness, and we should not rename agent simulation as that evidence.

For Q1 and Q2, independent users are not required to make the bounded product
mechanics decisions above.

They would be required later to claim that human authors find the feature
valuable, understandable, enjoyable, or preferable.

---

# 5. Selected product disposition

The coding-agent stress test supports:

## Premise Fitness

Keep as a documented method now.

Do not build a standalone runtime.

If repeated product work needs automation, prefer a small read-only structured
analysis surface supporting:

- target-environment persistence;
- batch opportunity comparison;
- revision delta;
- Genre Pack provenance;
- post-Discovery fitness delta.

## Architecture-aware reassessment

Retain as a narrow conceptual second pass:

    Story Opportunity
    -> Premise Fitness
    -> Story Discovery
    -> Post-Discovery Fitness Delta

Do not duplicate:

- F3 causal distinctness;
- F4 craft propagation;
- MANA audience-effect analysis.

## Evidence ceiling

These decisions are supported by controlled agent/product reasoning.

They do not eliminate the separate value of #305 / #310 for claims those tests
uniquely own.
