Recommendation: **publish-verified-testimony**

Why: The active commitment cluster (contested-history) currently groups two live constraints — monastery testimony being preserved and reactivated for this horizon, and the archive-protected fact (archive under treaty protection). The planning intent is explicit: return the testimony to public memory *without breaking the protected archive*. publish-verified-testimony satisfies both halves directly — it surfaces the testimony while leaving the treaty-protected original evidence secured, keeping the evidentiary chain intact. That chain-preservation matters because archive-protected exists precisely because the earlier admission was retracted and left the evidence vulnerable; re-exposing the underlying records now would recreate the exposure the treaty was built to prevent. This also keeps the option compatible with the explicit derived constraint that anything incompatible with archive-protected (like the excluded burn-archive proposal) is off the table — publish-verified-testimony doesn't touch or destabilize the protected holdings at all, it only authenticates and releases the testimony itself.

stage-protected-hearing, by contrast, presents the testimony *beside selected archive evidence*, which means exposing which records carry the strongest evidence — this creates exactly the kind of exposure pressure the series pressure line warns about ("every public correction gives hidden archivists reason to erase another witness") and edges toward weakening the protected chain, even though it stays nominally within treaty protections.

Principal tradeoff: publish-verified-testimony delays public release until authentication is complete — slower, but it fully preserves the evidentiary chain rather than risking it for immediate public pressure.

Deliberately excluded:
- burn-archive and ally-militia — never accepted, excluded from the Decision Map entirely.
- founding-record, public-admission, admission-retracted — dormant/superseded history that explains why archive-protected exists, but not surfaced as independent active constraints.
- broken-lantern / repaired-lantern — neither supports current continuity; repaired-lantern is recent but explicitly irrelevant, so I did not treat its recency as significance.
- The "official history vs. lived memory" thematic framing — noted as interpretive context only, not treated as a hard constraint in the recommendation itself.

This is a planning recommendation only — it does not create Book Direction and does not modify Canonical State.
