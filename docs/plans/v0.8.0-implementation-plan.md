> Release theme: **Decision Orchestration and Evidence Integration**

## Priority and Dependency Map

```
Tier 0 (Foundation):
  ├── 10: Structured output contracts  ─── schema design, no deps
  └── 4:  Decision lifecycle & lineage  ─── persistence changes, schema

Tier 1 (Subsystem Adapters):
  ├── 1: Direct reasoning integration   ─── depends on 10 for evidence schema
  ├── 2: Dedicated reconciliation integration  ─── depends on 10
  └── 6: Downstream impact preview      ─── depends on impact + reasoning data

Tier 2 (Cross-cutting):
  ├── 7: Decision conflict model        ─── depends on 1, 2, 6
  ├── 3: Bidirectional workflow         ─── depends on 1, 2
  └── 9: Workspace status improvements   ─── depends on 4

Tier 3 (Execution):
  ├── 8: Executable safe actions        ─── depends on 3
  └── 5: Stronger acceptance preparation ─── depends on 1, 2, 6, 7

Tier 4 (Delivery):
  ├── 11: End-to-end qualification harness  ─── depends on all above
  └── 12: Documentation                    ─── depends on all above
```

## Tier 0 — Foundation

### 10: Structured Output Contracts

**Goal**: Versioned, validator-backed schemas for every public artifact the Decision Workspace produces. Backward-compatible with v0.7.0 snapshots.

**Files modified**:
- `src/auteur/decision/models.py` — already has dataclasses; add schema version fields
- `src/auteur/decision/` — new `schemas.py` module for artifact type registries
- `src/auteur/convergence/models.py` — version CandidateRef evaluation storage

**Detailed changes**:

1. **Define versioned contract schemas** (new module `src/auteur/decision/contracts.py`):
   - `DecisionSnapshot_v1` — field-scoped schema with `schema_version = "decision-snapshot-v1"`
   - `EvidenceBundle_v1` — evidence artifact schema with source and freshness
   - `NextActionResult_v1` — typed next-action result
   - `AcceptancePreparation_v1` — acceptance readiness artifact
   - `ImpactPreview_v1` — impact preview result
   - Each schema: Pydantic `BaseModel` (migrate from `@dataclass` where appropriate) or a frozen dataclass with `to_dict()`/`from_dict()` that validates version field
   - Add `schema_version: str = "decision-snapshot-v1"` field to `AuthorDecision`
   - Add `snapshot_id: str` (content-hash-based, deterministic) to each snapshot

2. **Add backward-compatibility layer** to `DecisionStore` (in `persistence.py`):
   - On load: detect `schema_version`; if absent or `"decision-snapshot-v0"`, run a compat transform that fills empty fields from v0.7.0 shape
   - On save: always write current version
   - Test: load a v0.7.0-shaped JSON and verify all fields populate

3. **Add snapshot lineage**: Each snapshot carries `preceding_snapshot_id: str | None` for chain-of-decisions tracking

4. **Add serialization roundtrip tests**: `to_dict()` → JSON → `from_dict()` → verify all fields

5. **Add fixture factory** for each contract type: `make_decision_snapshot(**overrides)` returning a valid default instance

6. **Convergence CandidateRef**: add optional `evaluation_report_ids: list[str]` alongside legacy `evaluation_references` (which stays for compat through v0.8.x)

**Tests affected**: `test_decision.py::TestDecisionModels` — extend with contract version tests, serialization roundtrips
**New tests**: `test_decision_contracts.py` — versioned schema tests, compat loader

### 4: Decision Lifecycle and Lineage

**Goal**: Track decision snapshots as a chain; distinguish new decision from new snapshot of existing decision; record staleness/supersession causes; CLI inspection commands.

**Files modified**:
- `src/auteur/decision/models.py` — add lineage fields, snapshot metadata
- `src/auteur/decision/persistence.py` — snapshot chain support
- `src/auteur/decision/service.py` — lineage queries
- `src/auteur/decision/cli.py` — `history`, `lineage`, `diff` commands
- `src/auteur/decision/assembler.py` — needs-supersession detection

**Detailed changes**:

1. **Models**: Add to `AuthorDecision` (or a new `DecisionSnapshot` wrapper):
   - `snapshot_id: str` — deterministic hash of decision_id + snapshot timestamp
   - `preceding_snapshot_id: str | None`
   - `snapshot_reason: str` — enum of `"initial"`, `"refreshed"`, `"superseded"`, `"reopened"`, `"stale_detected"`
   - `supersession_chain: list[str]` — ordered IDs of decisions this one replaces
   - `lineage_root_id: str` — first snapshot in this decision's line
   - `lineage_depth: int` — how many snapshots deep

2. **Persistence**: `DecisionStore` changes:
   - `save_snapshot()` — accept `preceding_snapshot_id` param; auto-link chain
   - `load_lineage(decision_id) → list[AuthorDecision]` — all snapshots for this lineage in order
   - `load_snapshot_at(decision_id, snapshot_id) → AuthorDecision | None`
   - `list_lineages() → dict[str, list[str]]` — mapping lineage_root → [snapshot IDs]
   - `get_lineage_root(decision_id) → str`
   - `save_snapshot()` already prevents conflicting content — extend to log supersession

3. **Service**: `DecisionWorkspaceService`
   - `lineage(decision_id) → list[AuthorDecision]` — returns all snapshots
   - `history(decision_id) → list[dict]` — summary for CLI display
   - `diff(snapshot_id_a, snapshot_id_b) → dict` — field-level diff
   - `detect_supersession(decision_id) → str | None` — check if newer state supersedes

4. **CLI** — new commands:
   ```bash
   auteur decision history <decision-id>      # ordered snapshot list with reasons
   auteur decision lineage <decision-id>       # tree/chain visualization
   auteur decision diff <id-a> <id-b>          # field-level diff
   ```

5. **Assembler**: `derive_lifecycle_state()` — add `SUPERSEDED` lifecycle state; `compute_readiness()` — detect when a decision has been superseded by newer state

**Tests**: `TestDecisionLineage` class in `test_decision.py` — test chain linking, history queries, diff computation, supersession detection

## Tier 1 — Subsystem Adapters

### 1: Direct Reasoning Integration

**Goal**: Replace indirect `convergence.evaluation_references` reads with direct reads from the reasoning subsystem. Load critic/synthesis/evaluation artifacts by candidate ID.

**Files modified**:
- `src/auteur/decision/service.py` — add `ReasoningAdapter` integration
- `src/auteur/decision/` — new `adapters/reasoning_adapter.py`
- `src/auteur/decision/assembler.py` — use real reasoning data for freshness/readiness
- `src/auteur/reasoning/draft_review.py` — expose public query API for reports

**Detailed changes**:

1. **New adapter module**: `src/auteur/decision/adapters/__init__.py` + `src/auteur/decision/adapters/reasoning_adapter.py`
   - `ReasoningAdapter` class:
     - `__init__(self, project_root: Path)` — init chapter-scoped reasoning store
     - `get_candidate_reports(candidate_id: str) → list[dict]` — load synthesis reports keyed by candidate
     - `get_critic_report(critic_id: str, chapter_index: int) → dict | None`
     - `get_synthesis_report(review_id: str) → dict | None`
     - `detect_staleness(candidate_id: str, source_hashes: dict[str, str]) → EvidenceFreshness` — compare content hashes from reasoning's `ArtifactRevision`
     - `list_reasoning_evidence(candidate_id: str) → list[DecisionEvidence]` — convert reasoning findings to decision evidence
     - `get_missing_evidence(target_artifact_id: str) → list[str]` — identify candidates lacking reasoning

2. **Reasoning subsystem exposure**: In `src/auteur/reasoning/draft_review.py`:
   - Add public `load_candidate_review(chapter_index: int, review_id: str) → dict | None`
   - Add public `list_reviews_for_candidate(candidate_id: str, project_root: Path) → list[str]`
   - Ensure review JSON includes `candidate_id` field for cross-referencing

3. **DecisionService updates**: In `src/auteur/decision/service.py`:
   - Initialize `ReasoningAdapter` in constructor alongside other stores
   - `_decision_from_convergence_target()` — replace `cand_ref.evaluation_references` with `reasoning_adapter.get_candidate_reports(candidate_id)`
   - `_enrich_decision()` — add reasoning findings as evidence with `EvidenceSource.REASONING`, classification mapping (preserve nuanced findings, don't collapse to score)
   - `prepare_acceptance()` — replace reasoning-evidence check with real reasoning adapter query
   - Surface `NEEDS_EVALUATION` when reasoning adapter returns empty for a candidate

4. **Staleness detection**: `detect_staleness()` in adapter compares candidate source hashes against reasoning's `ArtifactRevision.content_hash`. When mismatch → `STALE`; set snapshot_reason = "source_changed".

5. **Evidence mapping**: Each reasoning critic finding becomes a `DecisionEvidence`:
   - `source_subsystem=REASONING`
   - `source_artifact_id=critic_id`
   - `claim= critic finding statement`
   - `evidence_type=REASONING_FINDING` (new EvidenceType)
   - `classification` mapped from critic severity (error→FACT, warning→DERIVED_INFERENCE, info→CONTEXTUAL_OBSERVATION)

6. **Candidate freshness**: In `CandidateSummary`, replace `reasoning_evidence: list[str]` (string references) with `reasoning_evidence: list[DecisionEvidence]` to carry full evidence. Backward compat: if loading old snapshot with `list[str]`, convert via compat layer.

**Tests**: `test_reasoning_adapter.py` — unit tests for adapter query methods, staleness detection, evidence mapping
**Existing test updates**: `test_decision.py::TestDecisionWorkspaceService` — update tests that set `reasoning_evidence=["ev-1"]` to use new shape

### 6: Downstream Impact Preview

**Goal**: Simulate consequences of accepting a candidate: show regeneration/reconciliation/review work likely needed; distinguish definite from inferred impact; no state mutation.

**Files modified**:
- `src/auteur/impact/analyzer.py` — expose simulation API
- `src/auteur/impact/models.py` — add `ImpactPreview` model
- `src/auteur/impact/cli.py` — `impact-preview` command
- `src/auteur/decision/service.py` — `impact_preview()` method
- `src/auteur/decision/cli.py` — `impact-preview` command registration

**Detailed changes**:

1. **Model**: Add `ImpactPreview` to `src/auteur/impact/models.py`:
   - `candidate_id: str`
   - `target_artifact_id: str`
   - `simulated_at: str` (ISO timestamp)
   - `definite_impacts: list[ImpactedArtifact]` — artifacts that WILL need regeneration
   - `inferred_impacts: list[ImpactedArtifact]` — artifacts that MAY need review
   - `unchanged_artifacts: list[str]` — artifacts confirmed unaffected
   - `downstream_work_summary: str` — readable summary of expected work
   - `impact_graph: dict` — dependency edges that would change

2. **Impact analyzer simulation**: In `src/auteur/impact/analyzer.py`:
   - `simulate_acceptance(candidate_id: str, project_root: Path) → ImpactPreview`
   - Walk dependency graph from target artifact
   - Classify each dependent: if structural dependency on changed content → `definite`; if transitive/review-only → `inferred`
   - No writes to canonical or accepted state
   - Deterministic comparison: `compare_downstream_cost(preview_a, preview_b) → dict` — naive scoring (definite count * 2 + inferred count)

3. **DecisionService**: Add `impact_preview(decision_id, candidate_id)`:
   - Returns `ImpactPreview` from simulation
   - Caches per (candidate_id, source_hash) for idempotency

4. **CLI**: New command:
   ```bash
   auteur decision impact-preview <decision-id> --candidate <candidate-id>
   ```
   Outputs `ImpactPreview` as formatted table or JSON.

5. **No state mutation**: Simulation runs entirely in memory. Use `ImpactAnalyzer` in read-only mode. Assert no files written to `.auteur/` or any canonical path.

**Tests**: `test_impact_preview.py` — simulate acceptance, verify definite vs inferred classification, confirm no writes
**Fixture**: deterministic project with known dependency graph

## Tier 2 — Cross-cutting

### 7: Decision Conflict Model

**Goal**: Make conflicting evidence a first-class concept. Model conflicts between impact, reasoning, convergence, and reconciliation evidence. Classify conflict type (factual/structural/interpretive/creative). Record subsystem of origin. Recommend resolution boundary.

**Files modified**:
- `src/auteur/decision/models.py` — enhance `DecisionConflict`
- `src/auteur/decision/assembler.py` — conflict detection
- `src/auteur/decision/service.py` — conflict API
- `src/auteur/decision/cli.py` — `conflicts` command

**Detailed changes**:

1. **Enhanced `DecisionConflict`** in `models.py`:
   - Add `conflict_type: ConflictType` enum: `FACTUAL`, `STRUCTURAL`, `INTERPRETIVE`, `CREATIVE`
   - Add `source_subsystem: EvidenceSource` — which subsystem produced each claim
   - Add `claims: list[dict[str, Any]]` — the conflicting claims (subsystem + claim text + evidence ref)
   - Add `resolution_boundary: ResolutionBoundary` enum: `RECOMPUTE`, `RECONCILE`, `REQUEST_AUTHOR_CHOICE`, `BLOCK_ACCEPTANCE`
   - Add `detected_at: str` — ISO timestamp

2. **Conflict detection** in `assembler.py`:
   - New class `ConflictDetector`:
     - `detect_conflicts(decision: AuthorDecision) → list[DecisionConflict]`
     - Evidence-Type classification:
       - Same artifact, different content hashes in impact vs reasoning → FACTUAL
       - Structure vs realization disagreement about sequence → STRUCTURAL
       - Reasoning critic disagreement → INTERPRETIVE
       - Author-intention vs realized-state mismatch → CREATIVE
     - Resolution boundary mapping:
       - FACTUAL → RECOMPUTE
       - STRUCTURAL → RECONCILE
       - INTERPRETIVE → `REQUEST_AUTHOR_CHOICE` (preserve nuance)
       - CREATIVE → `REQUEST_AUTHOR_CHOICE` or `BLOCK_ACCEPTANCE`
   - No subsystem is silently authoritative — all conflicting claims included in conflict record

3. **Service**: `DecisionWorkspaceService.conflicts(decision_id) → list[DecisionConflict]`
   - Runs `ConflictDetector.detect_conflicts()` for the decision
   - Returns all active conflicts (freshness=CURRENT)

4. **CLI**: New command:
   ```bash
   auteur decision conflicts <decision-id>  # list active conflicts with types
   auteur decision conflicts <id> --json     # machine-readable output
   ```

5. **Readiness integration**: `compute_readiness()` — if BLOCK_ACCEPTANCE conflicts exist → `BLOCKED`; if RECONCILE conflicts → `NEEDS_RECONCILIATION`; if REQUEST_AUTHOR_CHOICE → `NEEDS_AUTHOR_DECISION`

**Tests**: `test_decision_conflicts.py` — factual conflict detection, structural conflict, interpretive disagreement, creative divergence; verify resolution boundaries match

### 3: Bidirectional Guided Workflow Integration

**Goal**: `workflow next` queries the Decision Workspace. Decision actions rank alongside workflow actions. Safe decision actions can execute through the engine. Authority-bearing actions refused. No recursion.

**Files modified**:
- `src/auteur/workflow/rules.py` — `recommend_actions()` — integrate decisions
- `src/auteur/workflow/engine.py` — revalidate decision state; allow decision-safe actions
- `src/auteur/workflow/models.py` — add decision-aware action types
- `src/auteur/decision/assembler.py` — `compute_next_action()` — align with workflow integration

**Detailed changes**:

1. **Workflow action integration**: In `src/auteur/workflow/rules.py`:
   - `recommend_actions()` gains optional `decisions` param (list of `AuthorDecision`)
   - When decisions exist, inject decision-based actions into the action list:
     - Decisions at `READY_FOR_ACCEPTANCE` → prep a prepare-acceptance action
     - Decisions at `NEEDS_EVALUATION` → prep an evaluate action
     - Decisions at `NEEDS_AUTHOR_DECISION` → prep an inspect action
     - Decisions at `BLOCKED` → prep a review-blockers action
   - Decision actions are inserted BEFORE workflow-stage actions if they affect the current stage, AFTER otherwise
   - `workflow next` returns the single highest-priority action (decisions first when stage-appropriate)

2. **Decision state revalidation**: In `WorkflowEngine`:
   - Before executing a decision-originated action: re-read decision workspace, confirm the recommended action is still valid
   - If stale → return "re-evaluate" error without advancing
   - If decision resolved → skip

3. **Safe action execution**: In `WorkflowEngine.can_execute()`:
   - Allow decision actions flagged `safe_to_execute=True` through the engine
   - Block decision actions with `authority_level=AUTHORITY_BEARING` or `CANONICAL_MUTATION`
   - Current safe decision actions:
     - `evaluate-candidate` → safe
     - `compare-candidates` → safe
     - `refresh-impact-analysis` → safe
     - `prepare-acceptance` → safe
     - All others (resolve-conflicts, author-decision, etc.) → blocked

4. **Recursion prevention**: Engine already blocks `workflow` subcommands. Add:
   - Block `decision` subcommands that are authority-bearing (accept, approve, reject)
   - Allow only safe decision subcommands through automatic dispatch
   - Add `_FORBIDDEN_DECISION_SUBCOMMANDS` set alongside `_FORBIDDEN_SUBCOMMAND_PREFIXES`

5. **Child command failure**: Engine already handles this — `execute()` returns `executed=False` with exit code and stderr; no workflow state advancement.

6. **Preserve existing behavior**: When no decisions are open (empty DecisionWorkspace), `recommend_actions()` returns exactly the current list — no behavioral change.

**Tests**: `test_workflow_decision_integration.py` — decisions present/absent, safe/unsafe execution, stale revalidation, recursion prevention
**Existing test updates**: `test_workflow_rules.py`, `test_workflow_cli.py` — extend for decision-aware paths

## Tier 3 — Execution

### 8: Executable Safe Actions

**Goal**: Allow the workspace to perform genuinely safe operations: refresh impact analysis, refresh decision snapshots, run comparison, validate, inspect evidence — through the existing authority model.

**Files modified**:
- `src/auteur/decision/service.py` — safe action methods
- `src/auteur/decision/assembler.py` — mark actions safe_to_execute
- `src/auteur/workflow/engine.py` — safe action dispatch
- `src/auteur/decision/cli.py` — `refresh`, `revalidate` commands

**Detailed changes**:

1. **Safe action registry**: New `SAFE_DECISION_ACTIONS` set in `auteur.workflow.models`:
   ```python
   SAFE_DECISION_ACTIONS = frozenset({
       "refresh-impact-analysis",
       "refresh-decision-snapshots",
       "run-candidate-comparison",
       "run-deterministic-validation",
       "generate-reconciliation-proposals",
       "inspect-reasoning-evidence",
       "prepare-acceptance-evidence",
   })
   ```

2. **DecisionWorkspaceService safe actions**:
   - `refresh_impact_analysis(target_id) → int` — run ImpactAnalyzer, return findings count
   - `refresh_snapshots(decision_id=None) → int` — re-assemble and persist updated snapshots
   - `run_comparison(decision_id) → str | None` — run deterministic comparison, return comparison_id
   - `run_validation(decision_id) → list[str]` — run deterministic validation, return findings
   - `generate_proposals(artifact_id) → int` — generate reconciliation proposals
   - `inspect_evidence(decision_id, source) → dict` — return evidence by source subsystem

3. **Idempotency**: All safe actions log execution results. `refresh_snapshots` checks content hash before writing; if unchanged, skip write but update `last_checked` timestamp.

4. **Failure diagnostics**: Wrap each action in try/except; return `{"status": "failed", "error": str(e), "action": action_name}`. Never raise.

5. **Never execute**: The following remain forbidden for automatic execution:
   - Acceptance (`decision prepare-acceptance` with auto-execute)
   - Canonical mutation
   - Creative merge
   - Authority-bearing decisions

6. **CLI safe-action commands**:
   ```bash
   auteur decision refresh             # refresh all snapshots
   auteur decision refresh --decision <id>  # refresh one
   auteur decision revalidate <id>     # deterministic validation
   ```

**Tests**: `test_decision_safe_actions.py` — idempotency, failure handling, forbidden-action blocking

## Tier 4 — Delivery

### 11: End-to-End Qualification Harness

**Goal**: Build a canonical real-state acceptance harness that tests complete lifecycle scenarios. Install wheel, use fixture projects, verify exact exit codes and JSON, confirm no mutation.

**Files created**:
- `tests/qualification/` — new directory
- `tests/qualification/conftest.py` — runner infrastructure
- `tests/qualification/scenarios/` — one file per core scenario
- `tests/qualification/runner.py` — orchestration script

**Detailed changes**:

1. **Runner infrastructure** (`tests/qualification/runner.py`):
   - `QualificationRunner` — class that:
     - Builds the wheel via `hatch build`
     - Installs to a temporary venv via `pip install`
     - Creates fixture project directories with deterministic state
     - Executes CLI commands as subprocesses
     - Asserts exact exit codes and JSON output
     - Confirms no canonical/accepted-state mutations
     - Produces machine-readable qualification report (JSON)
   - Exit non-zero when any scenario is incomplete

2. **Core scenarios** (one per file under `tests/qualification/scenarios/`):
   1. **`scenario_impact_creates_decision.py`**: Run impact analysis → verify decision workspace shows a decision
   2. **`scenario_no_candidate.py`**: Decision exists but has no candidates → verify `NEEDS_CANDIDATE` readiness
   3. **`scenario_unevaluated_candidate.py`**: Candidate exists but no reasoning → verify `NEEDS_EVALUATION`
   4. **`scenario_candidate_comparison.py`**: Multiple candidates with reasoning → verify comparison available
   5. **`scenario_stale_reasoning.py`**: Source changes after reasoning → verify staleness detected
   6. **`scenario_reconciliation_conflict.py`**: Conflicts detected → verify `NEEDS_RECONCILIATION`
   7. **`scenario_author_choice.py`**: Creative choice needed → verify `NEEDS_AUTHOR_DECISION`
   8. **`scenario_acceptance_ready.py`**: All prerequisites met → verify `READY_FOR_ACCEPTANCE`
   9. **`scenario_blocked_acceptance.py`**: Acceptance blocked by conflict → verify blocked
   10. **`scenario_resolution_after_acceptance.py`**: After author resolves → verify lifecycle transition

3. **Fixture projects**: In `tests/qualification/fixtures/` — pre-built minimal projects with:
   - `story_identity.yaml`, `blueprint.yaml`, chapter outlines, scene files
   - `.auteur/` directory with convergence and decision state
   - Known content hashes for staleness detection

4. **No-mutation assertions**: Each scenario verifies:
   - No files written outside `.auteur/` decision, reasoning, or convergence directories
   - Canonical files (`story_identity.yaml`, `blueprint.yaml`, chapter `final.md`) unchanged
   - Accepted state (`chapters/*/accepted_candidate.yaml`) unmodified

5. **CI integration**: Add to `pyproject.toml`:
   ```toml
   [tool.pytest.ini_options]
   addopts = "-q --tb=short -W ignore::UserWarning"
   testpaths = ["tests", "tests/qualification"]
   ```

**Tests**: The harness IS the test — run `pytest tests/qualification/` as part of release pipeline

## Risk Assessment

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| Reasoning adapter requires reasoning subsystem changes | Medium | Medium | Add query methods to `draft_review.py`; backward-compatible |
| Reconciliation adapter coupling to expression layer | Medium | High | `ReconciliationAdapter` wraps calls; can be mocked for testing |
| Workflow decision integration changes existing `workflow next` behavior | Low | Medium | Gate behind `has_decisions` check; preserve exact existing behavior when no decisions |
| Contract schema migration for existing v0.7.0 projects | Low | Medium | Load-time compat transform; no data loss; tested roundtrip |
| Staleness detection across 3 subsystems gets complex | Medium | Low | Each adapter handles its own staleness; composite freshness = worst-of-all |
| Qualification harness installs wheel — CI dependency | Low | Low | Skips if `pip install` fails; scenarios testable without install |
| CLI argparse conflicts for new subcommands | Low | High | Register in v0.8.0 command group; existing `auteur decision` prefix avoids naming conflicts |
