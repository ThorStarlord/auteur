Review of commit 8f90cde8 (claim-basis verification and derived changes). Source files only.
Paths are relative to the worktree root. Findings are ordered most serious first.

1. Carried verifications are bound to the wrong numbering (studio_architecture_synthesis.py 263-266, 307-311, 371-381; browser/studio_architecture_synthesis.js 260-261).
_verification_criticism writes "judged s2 ... (The verifier cited: E5.)" using identifiers from the prior synthesis packet. The follow-up packet is numbered differently. The served follow-up body sends culmination null and handoffs [] (JS 260-261). When the prior synthesis named a culmination, its author_culmination evidence item is absent from the follow-up, so every later id (book_element, coverage, link) shifts by one. Trigger: prior synthesis with a culmination; the verifier cites E5, a Book element; in the follow-up, E5 is a different element and s2 is a different stage. The criticism text does not name the prior request or the claim's wording. Consequence: the follow-up's criticism assessment and changes_from_prior can attach the verifier's judgement to the wrong stage or citation. Fix: name the prior synthesis and quote the claim's wording in the criticism, and drop or translate the identifiers.

2. Stale and superseded verifications are accepted as criticism (synthesis.py 373-381, 410-418; verification.py 184-196; JS 228, 264, 671).
_verification_criticism checks only that the result exists and names the prior synthesis. It never consults the standing that _standing computes, and prepare does not check it either. Trigger: the author checks a claim (current), ticks "offer as criticism", then edits Story Vision or a Book element (both are in the evidence fingerprint). The panel shows "Stale" and disables the box, but view.carried keeps the request sha, load() never prunes it, and prepare sends it. A direct POST with the same sha is accepted. Consequence: a judgement about evidence that has since changed enters a new synthesis as current criticism. Fix: refuse unless standing is current; prune view.carried when a load returns.

3. A quote is not checked when no evidence is cited (verification.py 165; synthesis.py 463-464).
_grounded returns no problems when the cited list is empty, so the verbatim-quote check in design 12.4 is skipped. Trigger: judgment insufficient_evidence or creative_speculation, evidence [], quote "words not in the record". A probe through _check_verification accepted this. Consequence: the panel (JS 665) prints the quote in quotation marks as if it came from the record. Fix: refuse any quote when evidence is empty.

4. Superseded standing and a second judgement are unreachable (verification.py 194-196, 248-249, 268-269).
The request fingerprint excludes created_at (host_agent.py, build_host_agent_request), and the verification settings and packet derive only from the stored synthesis and claim. So each (synthesis, claim) has one request; latest_by_claim always names it; _standing never returns "superseded". A probe confirmed that changing created_at leaves the sha unchanged. Once completed, a different response is refused ("already completed this request"). A request whose pointer is missing (a crash between lines 248 and 249) also reads as superseded. Consequence: an author cannot obtain a second judgement of a claim, and design 12.3 ("superseded when a later verification of the same claim exists") is not implemented. Fix: key requests by a prepare sequence, or correct 12.3 and remove the branch.

5. Positional revision does not implement the documented rule (synthesis.py 628-629, 651).
Design 12.6 says an item in the same slot is revised when it keeps at least 30 percent of its words. The code computes Jaccard (intersection over union), which is stricter. Trigger: a stage corrected by lengthening, for example "The guild seals the archive after the flood" becomes a longer sentence that contains all six of its content words. Probe: containment 0.83, Jaccard 0.18. derived_changes reports stage_removed s1 and stage_added s1, the misreport that 12.6 says the rule prevents (Exercise F). Fix: measure the share of the prior item's words that remain.

6. Non-atomic response and result writes (verification.py 299-300; the same pattern at synthesis.py 794-795).
response.json is written before result.json. A crash between them leaves a response with no result. The retry check at line 268 compares only response.json, so a corrected response is refused and the request can be completed only by resubmitting the identical text. Consequence: the request is wedged, but only after a crash. Fix: compare against result.json, or write result first.

7. Served state handling (JS 545-550, 614-625).
loadVerifications clears view.verification in its catch whatever the token, so a late failed load can blank a newer panel. view.claimDrafts is keyed by claim ref only, so a pasted response for s1 of one synthesis appears under another synthesis's s1. The server refuses it by fingerprint, so nothing is written.

Checked and clear: the served panel guards a null view.verification (renderBasisChecks, latestCheck, prepareClaim), so no null dereference was found on an absent projection. No narrative or Architecture write was found; the new writes stay under synthesis/verifications and the existing synthesis pointer. Refused judgements are kept under refused/ and never reach result.json. The new paths do not re-enter the canvas lock.
