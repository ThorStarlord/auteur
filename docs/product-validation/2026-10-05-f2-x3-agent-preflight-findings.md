## Why this probe exists

Auteur already has substantial human, founder, synthetic, and deterministic
evidence. The purpose of this preflight is therefore not to rerun first-session
usability research.

It asks a narrower question:

> Before a real-provider #310 packet is available, what can the repository
> already tell us about the selected F2 + X3 frontier?

The probe intentionally does **not** generate prose with a provider and does not
pretend to observe a human author.

Run:

~~~bash
python scripts/f2_x3_agent_simulation_probe.py --json
~~~

## Finding 1 — accepted history and obsolete-plan precedence are mechanically strong

The preflight constructs accepted Chapters 1 and 2, records accepted realized
state, leaves an older Chapter-2 plan expecting the Lantern to remain an enemy,
then plans Chapter 3 after accepted state says the Lantern may be an ally.

Observed:

~~~text
accepted Chapters 1–2 visible downstream           PASS
accepted changed state visible                     PASS
obsolete enemy plan surfaced as divergence         PASS
historical plan silently rewritten                 NO
new Chapter-3 role preserved                       PASS
~~~

This strengthens the F2 hypothesis that Auteur can distinguish:

~~~text
what was planned
!=
what was accepted as happening
~~~

It does not prove the complete six-Chapter journey.

## Finding 2 — context relevance is not yet demonstrated

The preflight creates five accepted prior Chapters and six accepted events,
including one deliberately low-value detail.

Chapter-6 continuation receives all accumulated accepted events.

That means the current continuation path demonstrates:

~~~text
accepted-history availability
~~~

but not yet:

~~~text
relevance selection
~~~

Disposition:

**F2 accepted-history mechanics: PASS**  
**F2 context relevance: GAP / NOT ESTABLISHED**  
**Full F2 frontier: NOT QUALIFIED**

This does **not** warrant vector search, a graph database, or a generalized
retrieval subsystem.

If #318 activates, the next valid question is much smaller:

> Can bounded context composition select what Chapter 6 needs without losing
> accepted truth?

## Finding 3 — X3 has a concrete mechanical orientation gap

The current Beginner whole-Book projection is intentionally small and read-only.
Its contract exposes fields such as:

- planned/discovered/accepted Chapter counts;
- Book-expression status;
- reconciliation status;
- publication readiness;
- next technical command.

It does **not** itself project the selected X3 re-entry information:

- current Chapter;
- recent story changes;
- pending updates;
- next story-language action.

The browser also currently presents whole-Book state under:

> **Advanced: whole-book details**

and foregrounds:

> **Next technical action**

A query helper can infer a current Chapter from the URL, but that is not the same
thing as a persistent Book-orientation projection.

Disposition:

**X3 mechanical projection: GAP ESTABLISHED**

This is not a claim that a human dislikes the current UI. It is a direct mismatch
between the selected X3 mechanical contract and the current projection.
