# F2 + X3 Controlled Qualification Protocol

**Date:** 2026-10-04  
**Status:** ACTIVE evidence boundaries; the separate six-Chapter simulated reconstruction is complete, and human UX remains untested. See the 2026-10-20 current responsibility below.
**Narrative frontier:** F2 — Small-Book Longitudinal Coherence  
**Experience frontier:** X3 — Persistent Book Workspace  
**Authority:** protocol only; does not pre-authorize implementation, UI components, merge, release, or provider spend

## Purpose

Against contemporary integrated `main`, run one controlled small Book
through the complete author journey and let the **first material failure** select
the next bounded implementation responsibility.

The protocol must diagnose narrative capability and author experience
independently.

It must not begin by assuming the answer is a dashboard, timeline, sidebar,
graph, new database, retrieval subsystem, or new semantic layer.

---

## 1. Reference Book

Use one controlled ~6-Chapter Book with:

- 5–7 meaningful characters;
- one protagonist;
- one antagonist or primary opposition source;
- one supporting relationship arc;
- 3–4 recurring locations;
- two active plot threads;
- one governing engine;
- one subordinate engine or secondary pressure;
- a moderate target-experience trajectory.

Keep interpretive difficulty moderate so the test primarily stresses horizon,
state load, revision pressure, and persistence rather than premise ambiguity.

## 2. Required stress injections

### Chapter 1 — baseline establishment

Create and accept:

- Story core;
- Story shape / Structure;
- Chapter 1 plan;
- Chapter 1 prose.

Record the accepted outcome that later Chapters must remember.

### Chapter 2 — additive discovery

During drafting introduce:

- one previously unplanned but compatible character or relationship fact.

Keep the prose.

Do **not** require all models to synchronize before continuing.

Observe whether Chapter 3 planning can consume the accepted outcome plus an
explicit pending update.

### Chapter 3 — moved revelation

Move one planned revelation earlier.

This should create a Structure consequence without changing the core premise.

Observe:

- whether affected future beats are identified;
- whether unaffected commitments remain stable;
- whether the author can continue without reconstructing the dependency graph.

### Chapter 4 — meaningful change of intent

Change one material but non-thesis-level decision, for example:

- antagonist becomes reluctant ally;
- supporting relationship becomes central;
- intended tone becomes warmer/darker;
- secondary objective becomes primary for the remainder of the Book.

Observe selective consequence propagation.

### Chapter 5 — accumulated continuity pressure

Continue with:

- accepted earlier outcomes;
- one unresolved compatible story update;
- revised Structure;
- current character/relationship state.

Test whether context composition remains relevant rather than dumping the entire
Book into every reasoning surface.

### Chapter 6 — closure / whole-Book orientation

Complete the controlled Book.

Ask the system to present:

- what happened;
- what changed from the original plan;
- unresolved story updates;
- important continuity;
- the current state of major arcs;
- what would matter if the Book continued.

The output remains derived unless an existing owner explicitly accepts a change.

---

## 3. F2 narrative-capability questions

Evaluate:

1. Does Chapter N correctly use accepted outcomes from Chapter N-1 / N-2?
2. Does old Structure ever override accepted prose silently?
3. Are compatible pending updates usable without blocking continued writing?
4. Are contradictions surfaced before they make dependent reasoning false?
5. Does change propagation preserve unaffected commitments?
6. Are discoveries retained across Chapters?
7. Does whole-Book reasoning distinguish plan, realized history, pending change,
   and derived interpretation?
8. Does context selection stay relevant as the Book grows?
9. Does the repository preserve author authority through all corrections?

### F2 pass condition

F2 passes only if the complete six-Chapter journey can preserve coherent,
author-controlled longitudinal story state without requiring manual synchronization
of every internal model after each creative change.

---

## 4. X3 experience questions

Evaluate separately:

1. On re-entry, can the author identify the current Book and current Chapter?
2. Can the author tell what was accepted versus what is pending?
3. Is the next useful action legible without understanding internal layers?
4. Do continuity warnings remain ambient until they become decision-relevant?
5. Can the author find recent changes when needed?
6. Can the author resume after several simulated sessions without reconstructing
   the project manually?
7. Does accumulated state produce an information-density failure?
8. Do Creative / Guidance / Continuity / Deep-control capabilities still feel
   like one product rather than separate tools?

### X3 pass condition

X3 passes mechanically when the product can project enough state for an author
to re-enter and navigate the six-Chapter Book without exposing every backend
artifact as equal-priority UI.

Human claims about comfort, preference, elegance, or cognitive load still require
human evidence when asserted.

---

## 5. Independent verdicts

Always record two verdicts:

```text
F2 narrative capability: PASS / FAIL / BLOCKED
X3 experience capability: PASS / FAIL / BLOCKED
```

Examples:

```text
F2 PASS + X3 FAIL
-> story engine remembers correctly
-> repair orientation / information architecture / navigation

F2 FAIL + X3 PASS
-> interface is understandable
-> repair continuity / context composition / story-state behavior

F2 FAIL + X3 FAIL
-> identify the earliest independent failures
-> do not collapse both into one speculative rewrite
```

---

## 6. First-failure rule

Stop expanding the frontier when the first material failure is established well
enough to select an owner.

Classify it before implementation:

### Narrative / system

- context composition;
- Realization/state;
- Structure drift;
- change propagation;
- provenance/currentness;
- retrieval/relevance;
- authority workflow;
- infrastructure.

### Experience

- mental model;
- workflow;
- orientation/navigation;
- information architecture;
- progressive disclosure;
- interaction semantics;
- re-entry;
- information density;
- visual hierarchy;
- accessibility.

Implement the **smallest useful intervention at the lowest correct owner**.

Then rerun the same six-Chapter frontier before increasing scale.

---

## 7. Anti-prebuild rule

This protocol does not authorize any of these merely because they seem plausible:

- Book dashboard;
- persistent sidebar;
- timeline;
- relationship graph;
- multi-pane editor;
- new continuity database;
- vector retrieval layer;
- automatic reconciliation;
- new semantic layer;
- F3/F4 construction.

A component becomes warranted only when the controlled F2/X3 run exposes the
specific failure it would solve.
